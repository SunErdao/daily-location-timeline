# travel_legs.json 字段定义与示例

`travel_legs.json` 是整个流程里**最硬的位置证据**：把机票/火车票/大巴/自驾/船票变成机器可读的「出行腿」。

## 文件结构

```json
{
  "flights": [ ... ],   // 飞机票
  "trains":  [ ... ],   // 火车票(含高铁/普铁)
  "buses":   [ ... ],   // 大巴/口岸通关/顺风车(可选)
  "ships":   [ ... ]    // 船票(可选)
}
```

> v1 只要求 `flights`/`trains`；`buses`/`ships` 是 v2.0 增补的可选类别（陆路口岸、顺风车、轮渡同样是硬证据）。

## 单条腿字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `type` | ✅ | `flight` / `train` / `bus` / `drive` / `ship` |
| `dep_date` | ✅ | 出发日 `YYYY-MM-DD`（**当地时间日历日**） |
| `arr_date` | ✅ | 到达日；跨夜则 ≠ 出发日；以**到达地当地日历日**为准（海外跨时区防漂移） |
| `dep_min` | ✅ | 出发时间（分钟数，`10:00 = 600`），**出发地当地时间**；决定同日多段排序 |
| `arr_min` | ✅ | 到达时间（分钟数），**到达地当地时间** |
| `from` | ✅ | 出发城市，归一化两级短格式（国内 `省/市`，海外 `国家/城市`） |
| `to` | ✅ | 到达城市，同上 |
| `no` | ➖ | 航班号/车次/班次 |
| `seat` | ➖ | 席别（火车） |
| `stops` | ➖ | 经停站数组 `[{city, arr_min}]`——途中停靠但**不下车游玩**的站，记入到达日，不算停留段 |
| `status` | ✅ | `已使用` / `已购未用` / `用户口述`（订单没了但记得的行程） |
| `raw` | ✅ | 人类可读原文（如 `2024-07-18 杭州→兰州 MUxxxx`），便于回溯核对 |
| `estimate` | ➖ | 布尔。时刻是估算的（如口述「差不多 8 小时」）标 `true`；精确估算规则：缺到达时刻按 `出发 + 真实历时`，**宁保守勿激进** |

## 写法示例

### 国内跨夜火车（含经停）

```json
{
  "type": "train",
  "dep_date": "2024-07-24", "arr_date": "2024-07-25",
  "dep_min": 890, "arr_min": 660,
  "from": "青海/西宁", "to": "西藏/拉萨",
  "no": "Y839",
  "stops": [{"city": "青海/格尔木", "arr_min": 330}, {"city": "西藏/那曲", "arr_min": 570}],
  "status": "已使用", "raw": "2024-07-24 西宁→拉萨 Y839(经停格尔木/那曲, 示例)"
}
```

### 海外跨时区航班（红眼）

```json
{
  "type": "flight",
  "dep_date": "2025-07-02", "arr_date": "2025-07-03",
  "dep_min": 1420, "arr_min": 170,
  "from": "China/Shenzhen", "to": "Thailand/Bangkok",
  "no": "ZHxxx",
  "status": "已使用", "raw": "2025-07-02 深圳宝安 23:40 → 曼谷 02:50(+1, 当地)"
}
```

> 注意 `dep_min=1420`(23:40) > `arr_min=170`(02:50)：跨夜属正常，引擎按 `(dep_date, dep_min)` 排序。

### 口述补腿（订单丢失）

```json
{
  "type": "drive",
  "dep_date": "2026-09-28", "arr_date": "2026-09-28",
  "dep_min": 810, "arr_min": 1250,
  "from": "新疆/乌鲁木齐", "to": "新疆/富蕴",
  "no": "顺风车", "estimate": true,
  "status": "用户口述", "raw": "9/28 中午13:30乌鲁木齐出发顺风车,晚上8点多到富蕴[用户确认]"
}
```

### 陆路口岸通关（bus 类）

```json
{
  "type": "bus",
  "dep_date": "2026-06-12", "arr_date": "2026-06-12",
  "dep_min": 900, "arr_min": 1140,
  "from": "广东/深圳", "to": "广东/珠海",
  "no": "直达大巴", "status": "已使用", "raw": "6/12 深圳珠海直达大巴"
}
```

## 引擎如何消费这些字段

- **排序**：全部腿按 `(dep_date, dep_min)` 全局排序，串成物理轨迹链。
- **每日事件**：`dep_date` 产生 `(_dep)` 事件、`arr_date` 产生 `(_arr)` 事件；跨夜中间天标为到达城市（在途）。
- **时间感知判定**：每日有效时段 07:00–24:00 内按 `dep_min/arr_min` 切片段，停留最久城市胜出。
- **gap-fill 双闸**：链不断（前腿 `to` == 后腿 `from`）且 `1 <= gap <= MAX_GAP` 才填充；链断回落消费层。
- **transit_leg 跟踪**：到达事件只认当前在途腿，过滤陈旧到达污染。

## 常见错误

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| `arr_date` 写成出发日 | 到达日整天没证据，可能被消费层带偏 | 跨夜腿 `arr_date` 写到达日 |
| 忘记 `stops` | 经停日「当日全部城市」缺经停城市 | 经停站记入到达日 |
| `dep_min` 用当地时间之外的口径 | 同日多段排序错乱 | 时刻一律当地时间 |
| 口述行程不补腿 | 中间天被误标回老家 | `status: 用户口述` + `estimate: true` |
| 城市 format 混用（`浙江/杭州` vs `浙江省/杭州市`） | 归一化前比较失效 | 全程归一化短格式 |
| 大环线只记头尾 | 中间天被消费层拽回老家 | 补中间关键腿（城市+日期即可，时刻可 `estimate`） |
