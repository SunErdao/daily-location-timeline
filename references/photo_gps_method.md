# 照片 EXIF GPS 判定方法与实战教训

照片/视频的 EXIF GPS 是 **L0 级硬证据**（直接锚定物理位置）。当支付账单滞后或缺失时
（如当年账单未出、纯旅行期），它是补全逐日轨迹的主力。

## 一、为什么照片 GPS 有效

- 拍照那一刻「人 + 设备」一定在拍摄地——比任何消费记录都硬。
- 全球标准：EXIF/GPS 字段不分国内海外，iPhone/Android/相机/无人机（DJI）都带。
- 多设备混合库同样可用（按设备分别提取后合并）。

## 二、操作流程

### 1. 批量提取（exiftool）

```bash
exiftool -json -DateTimeOriginal -GPSLatitude -GPSLongitude -r \
  -ext jpg -ext jpeg -ext heic -ext png -ext mp4 -ext mov \
  /path/to/photos/ > photo_gps_raw.json
```

- `-r` 递归子目录；`-ext` 限定媒体格式（跳过非媒体）。
- 输出 JSON 数组，每条含 `SourceFile / DateTimeOriginal / GPSLatitude / GPSLongitude`。
- **时间口径**：`DateTimeOriginal` 是拍摄设备**本地时间**——与票务的「当地时间」口径一致，跨时区旅行按设备时区归日。

### 2. 逐日判定（scripts/photo_gps_judge.py）

```bash
python3 scripts/photo_gps_judge.py photo_gps_raw.json -o photo_daily_judge.json
```

脚本做的事：
1. 按 `DateTimeOriginal` 归日（跳过无日期/无 GPS 条目，分别统计）；
2. **反向地理编码**：每张照片坐标 → `city_coords.json` 里最近城市；
3. **时间感知聚合**：按有效时段（07:00–24:00）内各城市覆盖的照片数/时长，选主城市；
4. **三道保险**（见下节）逐日审计，问题日打 ⚠️ 标记。

### 3. 并入最终判定

把逐日结果作为 `L0` 级证据并入整合阶段（`rebuild_final.py` 的证据体系）；
与出行腿冲突的日子，用「出行腿时刻 + GPS 序列」人工核对。

## 三、三道保险（全部必做，缺一个都可能出错）

### 保险 1：距离审计（防城市库缺目的地）

- 规则：照片点距匹配城市中心 `> 0.3°`（约 33km）→ 当日标 ⚠️ 需人工复核。
- **为什么**：`nearest_city()` 只会返回库里**最近**的城市，不会告诉你「其实都不近」。
- **实战教训**：坐标库缺「新疆/阜康」，天池景区（43.90°N, 88.12°E）两天的 358+370 张照片
  被就近匹配到 40km 外的省会乌鲁木齐——距离 0.367°/0.376°，若做了距离审计立即暴露。
- **解法**：复核属实的，把真实目的地坐标补进 `city_coords.json`（景区/县城坐标皆可）。

### 保险 2：单点飞地检测（防孤立噪声点）

- 规则：当天仅 1–2 个 GPS 点、且远离前后邻日的位置 → ⚠️ 不可直接采信。
- **为什么**：他人分享的照片、带水印定位的转发图、设备 GPS 漂移都会产生孤立点。

### 保险 3：时区口径统一

- EXIF 时间 = 设备本地时间。跨时区旅行时：设备没调时区 → 照片日期与当地日历日可能差一天；
  设备自动调时区 → 与「票务当地时间」一致。**先确认设备行为，再统一口径。**

## 四、已知局限（诚实声明）

| 局限 | 说明 | 缓解 |
|------|------|------|
| 截图/转发图 GPS 不可信 | 微信保存的 `image_*.jpg`/`mmexport*.jpg` 常无 GPS 或为他人坐标 | 飞地检测 + 按文件名来源过滤 |
| 拍摄时间 ≠ 全天位置 | 一天只有 2 小时有照片 → 只证明那 2 小时 | 与出行腿/消费层合成，不单独定全天 |
| 夜间/室内无照片 | 有效时段内照片稀疏的城市可能缺位 | 兜底到消费层/出行腿 |
| GPS 坐标漂移 | 低端设备/室内定位误差可达数 km | 审计阈值 0.3° 远大于漂移，不误伤 |
| 城市库需人工扩充 | 初版坐标库只含常见城市 | 按到访地补坐标（每次审计警告日时顺手补） |

## 五、实战案例：天池两天误判乌鲁木齐

1. **现象**：9/26–27 判定为「新疆/乌鲁木齐」，但用户记忆是在天池。
2. **核查**：`photo_gps_raw.json` 里两天共 728 张照片，GPS 中心 (43.90, 88.12) = 阜康天池景区核心；
   但逐日反查结果全是「乌鲁木齐」，匹配距离 0.367° ≈ 40km。
3. **根因**：城市坐标库没有「阜康/天池」，`nearest_city()` 返回了最近的乌鲁木齐。
4. **修复**：距离审计先暴露 → 补入阜康坐标 → 重跑 → 两天正确归「新疆/阜康」。
5. **沉淀**：任何「GPS 指向明确但城市反常」的日子，先查匹配距离，再查坐标库覆盖。
